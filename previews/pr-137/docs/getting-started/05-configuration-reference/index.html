Configuration Reference

Complete reference for all Joulie environment variables. These are set via Helm values or directly in the Deployment/DaemonSet manifests.

Defaults listed below are the code defaults. The Helm chart (charts/joulie/values.yaml) overrides some of them: notably, the controller manager NODE_SELECTOR defaults to joulie.io/managed=true in the chart even though the code default is node-role.kubernetes.io/worker.

Booleans. The agent, the controller manager and the simulator read every on/off variable the same way: true, 1, yes or on, and false, 0, no or off, in any case, with surrounding spaces ignored. Unset or empty means the default. Any other value keeps the default and logs one warning naming the variable, so a typo never flips a switch. The exceptions are SIM_OTEL_FILE_METRICS, OTEL_SDK_DISABLED and fakesmi’s HWEMU_UNPRIVILEGED, whose rows say how they are read.

Images

The image tag values (agent.image.tag, controllerManager.image.tag, schedulerExtender.image.tag, and image.tag in the simulator chart) default to empty, which pulls the chart’s appVersion: a released chart runs its release’s images, a chart from a checkout (appVersion: latest) the newest stable release. Every image is a multi-arch index of linux/amd64 and linux/arm64.

Details: Configuration notes, Images.

Agent governor control

The agent always publishes its node’s CPU and GPU governors in NodeHardware (Governor discovery). It writes the presets of its NodeTwin only with GOVERNOR_WRITES true, and the controller manager sets them only with GOVERNOR_CONTROL on (Governor control).

VariableDefaultChartDescription
GOVERNOR_WRITESfalsefalseWrite the governor presets. false writes none and reports disabled, but still puts back, once, the settings an earlier run changed (result restored).
GOVERNOR_RESTORE_ON_EXITtruetrueOn SIGTERM or SIGINT, put the baseline back before the agent exits. SIGKILL and OOM kills restore nothing.
  • Writes need the agent’s /host-sys mount, root user and privileges, as the chart gives; without them the result is refused (NodeHardware writable: false).
  • NVIDIA presets need nvidia-smi in the agent (Agent GPU tools); without it the result is error.
  • HTTP control mode and pool mode write no governor (unsupported).
  • What each preset becomes per CPU driver and GPU family: CPU support, GPU support. Results, retries and restores: Governor control. Check them with:
kubectl get nodetwins -o custom-columns=NODE:.spec.nodeName,CPU-GOV:.status.controlStatus.cpuGovernor.result,CPU-NATIVE:.status.controlStatus.cpuGovernor.applied,GPU-GOV:.status.controlStatus.gpuGovernor.result,GPU-NATIVE:.status.controlStatus.gpuGovernor.applied

Agent GPU tools

The agent reads and caps NVIDIA GPUs by running nvidia-smi from its PATH. AMD and Intel GPUs need no tool, only the chart’s root agent and writable /host-sys: the agent writes the amdgpu power1_cap files, or the i915 or xe power1_max or power2_max files, with backend host-intel (Agent host backends).

The agent image ships no GPU tool and no C library: bring the driver’s tools and libraries in with agent.runtimeClassName (such as the NVIDIA container runtime), or with agent.extraVolumes, agent.extraVolumeMounts and agent.extraEnv. No recipe has been verified on a real NVIDIA node yet, so after installing check every GPU node:

kubectl get nodetwins -o custom-columns=NODE:.spec.nodeName,GPU:.status.controlStatus.gpu.result,MESSAGE:.status.controlStatus.gpu.message

A tool that cannot run shows error with a message starting gpu inventory failed, or blocked with no supported GPU backend detected; the GPUs then keep their limits. Details: Configuration notes, Agent GPU tools.

Managed nodes without an agent

The controller manager plans every managed node, agent or not. The NodeTwin condition AgentReporting (the Agent column of kubectl get nodetwins) is True while an agent publishes the node’s NodeHardware, and False (NoNodeHardware, or NodeHardwareStale after 15 minutes without a write) when the caps are planned but not enforced. joulie_twin_nodes_agent_reporting counts the nodes per status and reason (Twin agent coverage). Usual causes: a taint the agent does not tolerate, a node outside agent.daemonset.nodeSelector, or an image without the node’s platform.

kubectl get nodetwins -o custom-columns='NODE:.spec.nodeName,AGENT:.status.conditions[?(@.type=="AgentReporting")].status,REASON:.status.conditions[?(@.type=="AgentReporting")].reason'

Details: Configuration notes, Agent.

Measured node power

The controller manager writes each node’s measured power to NodeTwin.status.powerMeasurement.measuredNodePowerW, from Prometheus (NODE_POWER_SOURCE=prometheus, which the chart sets) or from one OTLP JSON document per node (http). The default preset otel reads hw.energy or hw.power of the cpu and gpu components, keyed by k8s.node.name; Input metrics (OpenTelemetry) has every preset query and the Prometheus settings.

The Chart column is what charts/joulie/values.yaml sets; “unset” means the code default applies.

Governor control

Off by default. With GOVERNOR_CONTROL on, the controller manager writes a vendor-neutral governor preset into each managed node’s NodeTwin (spec.cpu.governor, spec.gpu.governor) by the profile it runs at, and the agent maps it to native settings once it runs with GOVERNOR_WRITES true. Which node gets which preset: Governor policy.

VariableDefaultDescription
GOVERNOR_CONTROLoffoff, cpu (CPU governors only), gpu (GPU governors only) or all.
CPU_GOVERNOR_PERFORMANCE_PRESETperformanceCPU preset of performance nodes: performance (highest frequency at any load), balanced (demand-driven, quick ramp) or efficiency (demand-driven with an energy bias).
CPU_GOVERNOR_ECO_PRESETefficiencyCPU preset of eco nodes. Provisional: it does not pass the simulator’s governor exploration as a default for every CPU driver, and it lengthens compute-bound bursts.
CPU_GOVERNOR_ECO_BOOSTemptyon or off: frequency boost (turbo) with the eco preset, on nodes whose agent found a boost control (status.cpu.governor.boost). Empty leaves boost alone.
CPU_GOVERNOR_ON_GPU_NODESfalseWrite the CPU governor on GPU nodes too.
GPU_GOVERNOR_PERFORMANCE_PRESETemptyGPU preset of performance nodes: auto, sustained, efficient, low, peak, or empty for none.
GPU_GOVERNOR_ECO_PRESETefficientGPU preset of eco nodes; set it to an empty value to write none.
GPU_GOVERNOR_ECO_CEILING_PCT_OF_MAX80Compute clock ceiling of the efficient preset, in percent of the GPU’s maximum compute clock, in (0, 100]. Written only with efficient; a value out of range gives 80. Provisional (governor exploration).
GPU_GOVERNOR_MODEL_PRESETS_JSON{}Presets per GPU model: {"<model>": {"performance": "<preset>", "eco": "<preset>", "ecoCeilingPctOfMax": <pct>}}, keyed like GPU_MODEL_CAPS_JSON. A field left out keeps the default, "" writes none for that model, and an invalid field is dropped with a warning.
GPU_GOVERNOR_SUSTAINED_ONLY_MULTI_GPUfalseIf true, a node whose GPU preset is sustained gets it only while a running pod on it requests 2 or more GPUs (units of any GPU resource: whole GPUs, MIG devices, partitions, shared replicas), and no GPU governor otherwise.

GPU presets: auto is the vendor default; sustained holds memory and fabric clocks at their maximum (no default selects it); efficient caps the compute clock at the ceiling; low and peak are for experiments. All defaults are provisional until measured. Meanings: Hardware modeling; which node gets which: Governor policy.

The overview dashboard’s “Agent: Governors” row plots the presets in effect (joulie_agent_governor_state) and the writes per result (joulie_agent_governor_writes_total). Details: Configuration notes, Governor control.

Grid carbon intensity

Joulie ships no carbon intensity provider. If you already export one to Prometheus, point FACILITY_CARBON_INTENSITY_QUERY at it, with ENABLE_FACILITY_METRICS=true, and say what the value is:

controllerManager:
  env:
    ENABLE_FACILITY_METRICS: "true"
    FACILITY_CARBON_INTENSITY_QUERY: 'watttime_co2_moer{region="CAISO_NORTH"}'
    FACILITY_CARBON_INTENSITY_UNIT: "lbsCO2/MWh"
    FACILITY_CARBON_INTENSITY_SIGNAL: "marginal"

The query must return one series, so select the cluster’s grid zone with a label matcher. The value is converted to gCO2eq/kWh and exported as joulie_grid_carbon_intensity_grams_per_kW_h{joulie_grid_carbon_intensity_signal}; no policy acts on it yet. Details: Configuration notes, Grid carbon intensity.

Deprecated aliases, removed in v0.4.0: FACILITY_AMBIENT_TEMP_METRIC, FACILITY_IT_POWER_METRIC, FACILITY_COOLING_POWER_METRIC, the former names of the first three query variables. They are read only when the new name is unset, with a warning naming the replacement, and the bare metric name they hold keeps its meaning.

Node topology

Optional node labels give per-rack PSU stress and per-zone cooling stress:

  • joulie.io/rack: physical rack identifier (e.g., rack-1)
  • joulie.io/cooling-zone: cooling zone identifier (e.g., zone-a)

With them, PSU stress is computed per rack: the rack power input (FACILITY_RACK_POWER_QUERY) when it reads that rack, otherwise the sum of the estimated power of the rack’s nodes. A twin’s ambient temperature is the most local one known: the node’s inlet (FACILITY_NODE_INLET_TEMP_QUERY), then its cooling zone’s (FACILITY_ZONE_AMBIENT_TEMP_QUERY), then the outdoor ambient.

Nodes without the labels use cluster-wide stress, and still their inlet temperature when the facility reads one.

Simulator power limits

The simulator (simulator/cmd/simulator) reads these at startup. For a node the hardware catalogue matches, an unset variable leaves the field to the catalogue; the built-in default applies only to hardware it does not know. A node class key (in parentheses) wins over both, and 0 or less counts as unset (wiki: CPU power model, Where the numbers come from).

VariableDefaultDescription
SIM_P_MAX_Wsockets x catalogue TDP, else 420Peak CPU power of the generic model, at full load and full frequency (pMaxW). A node with a measured curve uses the curve instead.
SIM_BETA_FREQ1.43Exponent of the frequency scale in the CPU’s dynamic power, on the generic model and on a measured curve: P = P(0) + (P(u) - P(0)) x f^beta. Its fit is on the wiki’s CPU power model.

Simulator physics step

Outside the emulate-mode cluster spec, the simulator (simulator/cmd/simulator) advances a node’s model only in a physics step, in simulated time, split into equal substeps (Power Simulator).

VariableDefaultDescription
SIM_POLL_INTERVAL15s (chart: 8s)Kubernetes mode: how often the simulator lists pods and nodes. A value of 0 or less logs a warning and takes 15s.
SIM_PHYSICS_TICK1sKubernetes mode without emulate mode: every modelled node is stepped by the wall time since the last tick, in substeps of at most 100 ms. A value of 0 or less logs a warning and takes 1s. In emulate mode SIM_EMULATE_TICK steps them instead, and standalone mode steps them on its own tick.
SIM_SA_SUBSTEPSIM_SA_DTStandalone mode: the longest physics substep, in simulated seconds; each SIM_SA_DT tick is split into equal substeps no longer than this. Shorter follows the cap, frequency and thermal lags more closely, at the cost of run time.

Simulator hardware emulation

fakesmi (simulator/cmd/fakesmi) stands in for nvidia-smi, rocm-smi and amd-smi on an emulated node. It runs as the tool its name says, through a bin/<tool> link, and reads and writes the node’s emulated hardware files instead of a driver. The agent does not read these variables; only fakesmi does.

VariableDefaultDescription
HWEMU_SYS_ROOT/host-sysThe emulated node’s sys/ directory, where the amdgpu PCI and hwmon attributes live. The default is where an emulated agent pod mounts it.
HWEMU_STATE_ROOT/emu/stateThe emulated node’s state/ directory, with tools.json (the tools the node has) and the GPU state. The default is where an emulated agent pod mounts it.
HWEMU_ROOTFS/The file system the real tool would run in, where fakesmi looks for what the tool needs before it runs (below). The default is the agent container’s own root.
HWEMU_UNPRIVILEGEDfalseRun the tools as a user without root would: 1, true or another word Go’s strconv.ParseBool reads as true; anything else, unset included, means root. Sets then fail or do nothing, as the real tools do without root (nvidia-smi -pl exits 4 with Insufficient Permissions); reads work.

A tool that tools.json does not list exits 127 with fakesmi: <tool> is not installed on this emulated node.

A listed tool first checks, under HWEMU_ROOTFS, that the files the real tool needs exist (the ELF loader, the C libraries and NVML for nvidia-smi, python3 for rocm-smi and amd-smi), and fails with the real tool’s exit code and message when one is missing. Details: Configuration notes, Simulator hardware emulation.

Simulator emulate mode

In emulate mode the simulator (simulator/cmd/simulator) emulates the bare-metal nodes a cluster spec lists, with a sysfs tree, /proc/cpuinfo and GPU tool state per node under SIM_HWEMU_ROOT/<node>/ that an unmodified agent caps as a real node. /control/<node> answers 409 for an emulated node. See Emulate Mode.

VariableDefaultDescription
SIM_EMULATEfalseTurn emulate mode on. Refused with SIM_STANDALONE, with an empty SIM_CLUSTER_SPEC, and with SIM_WORKLOAD_MODEL=legacy, since a legacy trace cannot drive emulated nodes.
SIM_CLUSTER_SPEC(empty)Path of the cluster spec, a sim.joulie.io/v1alpha1 ClusterSpec such as tests/simcluster/specs/smoke.yaml: each node, its hardware profile, pool, rack and cooling zone, and the facility.
SIM_HWEMU_ROOT/var/lib/joulie-hwemuDirectory of the emulated trees, one <node>/ per spec node. One simulator holds it at a time; a second one fails to start.
SIM_HWEMU_FUSEfalseServe each spec node’s sys and state through FUSE at SIM_HWEMU_ROOT/fuse/<node>/, so writes and counters behave as the kernel’s do (FUSE mode). Needs /dev/fuse, and as root CAP_SYS_ADMIN; another user needs fusermount3.
SIM_EMULATE_TICK1sPhysics tick: every spec node advances to wall time once per tick; a late tick is caught up by the next. The nodes outside the spec are stepped on the same tick (see “Simulator physics step”).
