Simulator Metrics

This page lists every metric and event the simulator emits, to write a query or a dashboard against it. There are three kinds:

KindWhereMode
Prometheus metrics about the simulator itself (joulie_sim_*)scraped at /metricsevery mode
OpenTelemetry metrics and events about the emulated nodes and the facilitymetrics pushed as OTLP JSON over HTTP; events in events.jsonl, pushed when a logs endpoint is setemulate mode
Compatibility exporters: the Prometheus formats of Kepler, dcgm-exporter and the ROCm device-metrics-exporter/exporters/<name>/metrics, opt-inemulate mode

The OpenTelemetry names are spelled once, in pkg/otel/semconv, and the controller manager reads the same names back from Prometheus. Their Prometheus spelling is computed by pkg/otel/promname.

Prometheus metrics at /metrics

Served at /metrics on the simulator’s listen address (SIM_ADDR, default 127.0.0.1:18080, and :18080 in a pod). The JSON debug endpoints are listed under HTTP API.

OpenTelemetry metrics (emulate mode)

The names follow the OpenTelemetry semantic conventions v1.44.0 (schemaUrl: https://opentelemetry.io/schemas/1.44.0 on every resource and scope); names no convention covers use the prefix joulie.. Points are cumulative and carry the time of the export that sends them. How they are sent: Simulator telemetry export.

Producer rules

Only readings a real collector could measure are emitted, so a virtual machine node gets no hw.* metric. Whole-host energy is only hw.host.energy, never hw.energy, so a sum over hw.energy never counts the host twice. Counters never decrease, not even across a simulator restart.

Prometheus

A Prometheus started with --web.enable-otlp-receiver accepts the push at /api/v1/otlp/v1/metrics. Its settings (promoting k8s.node.name and host.name, the translation strategy, the out-of-order window), the spelling of every name under the other translation strategies, and the pitfalls are under Prometheus settings, Name translation strategies and Pitfalls. The full table for every name is pkg/otel/promname/testdata/prometheus-names.tsv.

Events (emulate mode)

Events are OpenTelemetry log records with an eventName, on their node’s resource; read the attributes, not the body. They are always appended to events.jsonl in SIM_OTEL_FILE_DIR and pushed only when a logs endpoint is set.

Compatibility exporters (emulate mode)

SIM_EXPORTERS turns on exporters that reproduce the Prometheus format of a pinned release of a real exporter, computed from the same counters the agent reads, to test Joulie’s kepler and kepler-legacy input presets and Collector bridges. The OpenTelemetry export above is the default.

Under a cap the idle and dynamic modes can add up to more than the node draws (kepler-legacy under a cap). A node without RAPL emits nothing.
